# Preparing a release

Release 1 is version `0.1.0` and targets Android plus a Linux x86_64/amd64
OBS source. ARM/ARM64 is not in the first binary release. The release uses
the latest OBS Studio version installed and tested in the release environment;
the exact `libobs` version is recorded with the Linux artifact.

## Android release signing

The public APK must be signed with a release keystore. Keep the keystore and
passwords outside the repository. The Gradle build accepts these environment
variables:

```text
ANDROID_SIGNING_STORE_FILE
ANDROID_SIGNING_STORE_PASSWORD
ANDROID_SIGNING_KEY_ALIAS
ANDROID_SIGNING_KEY_PASSWORD
```

With those values configured:

```bash
./android/gradlew -p android assembleRelease --console=plain
```

Without them, Gradle may produce an unsigned release APK for local inspection,
but that file must not be published as the downloadable release APK.

## Linux plugin artifact

On the supported x86_64 build environment:

```bash
./scripts/release/package-linux-plugin.sh
```

The script builds and tests the native source, verifies that the module is an
x86_64 ELF plugin, records the installed `libobs` version, and writes a tarball
and SHA-256 checksum under `build/release/`.

## GitHub release contents

Each public release should include:

- the CamBridge project name and `@louisemalvin` creator attribution;
- the signed Android APK;
- the Linux x86_64/amd64 OBS plugin tarball;
- SHA-256 checksum files;
- the source archive generated by the hosting service; and
- release notes naming the tested OBS version, Linux dependencies, and the
  trusted-LAN/no-authentication limitation.
- the repository [security policy](../SECURITY.md).

The release workflow in `.github/workflows/release.yml` publishes these files
when a matching `v0.1.0`-style tag is pushed. It requires repository secrets
named `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`,
`ANDROID_KEY_ALIAS`, and `ANDROID_KEY_PASSWORD`.
