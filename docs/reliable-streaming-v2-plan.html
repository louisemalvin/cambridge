Luna implementation contract · 4 August 2026

One reliable path from phone video to OBS.

Replace custom UDP recovery work and reverse control with a sender-initiated SRT session. Prove the complete path using an Android emulator video-file camera, then keep Android and iOS behind the same source-neutral contract.

Selected architecture H.264 in MPEG-TS over encrypted SRT

Mobile is the caller. Rust/GStreamer is the listener. The persistent v4l2loopback writer stays alive while ingest connects, disconnects, retries, or fails.

Mandatory end-to-end proof Emulator → receiver → OBS Moving sample video, not a synthetic host-only shortcut

The ingest lifetime and output lifetime are separate. OBS never needs to reopen its source when the phone reconnects.

Connection model

One direction

Phone initiates everything

The sender discovers or manually selects the receiver, creates a session, connects SRT, reads status, and deletes the session.

Implemented

No reverse control

No desktop subnet scan, Android listener, inferred peer address, or desktop request that wakes the phone camera.

Portable

Native media adapters

Android and iOS keep native camera and encoder code. They share wire values and conformance fixtures, not platform frame types.

Session state and recovery

stateDiagram-v2
  [*] --> Idle
  Idle --> Allocating: POST /v2/sessions
  Allocating --> Listening: SRT listener ready
  Listening --> Connected: accepted caller
  Connected --> Receiving: first decoded frame
  Receiving --> Reconnecting: caller lost
  Reconnecting --> Connected: same session reconnects
  Reconnecting --> Expired: grace exceeded
  Listening --> Expired: connect deadline exceeded
  Receiving --> Stopping: DELETE or sender stop
  Listening --> Stopping: DELETE
  Connected --> Stopping: DELETE
  Stopping --> Idle: ingest cleanup complete
  Expired --> Idle: ingest cleanup complete
  Allocating --> Failed: pipeline or output error
  Listening --> Failed: pipeline error
  Connected --> Failed: decoder error
  Receiving --> Failed: decoder or output error
  Failed --> Idle: cleanup complete

receiving means a decoded frame reached the output boundary. Socket activity alone is never treated as working video.

!
Standby is part of reliability.
The last camera frame must be cleared as soon as live ingest is lost. The virtual camera returns to a black waiting frame while SRT retries, so OBS never presents a stale image as live.

Platform boundaries

Android

RootEncoder SRT adapter

Use the emulator video-file camera through the existing camera source. Replace only transport construction. Pass a typed SRT endpoint to StreamEngine.

Gate RootEncoder SRT is upstream beta. Prove encryption, stream ID, stop, and reconnect before refactoring the app around it.

iOS

IOSMediaEngine adapter

Start with deterministic file video, H.264, MPEG-TS, and SRT. HaishinKit is the first candidate. Official libsrt remains the adapter fallback.

Do not claim runtime support without macOS build and integration evidence.

Receiver

GStreamer SRT source

srtsrc replaces udpsrc. The existing parse, decode, bounded raw output, and persistent v4l2 writer remain behind clear crate boundaries.

Receiver core owns every default and lifecycle transition.

Scope guardrails

In scope

  • SRT media transport and sender-initiated control
  • Receiver state, metrics, recovery, and persistent output
  • Android emulator to OBS proof
  • Android and iOS adapter boundaries
  • Deletion of superseded connection code

Out of scope

  • Camera, lens, stabilization, zoom, or preview improvements
  • Audio and H.265 before baseline gates
  • WAN, cloud relays, TURN, or non-Linux output
  • Adaptive bitrate before fixed-bitrate reliability
  • Untrusted-network security claims while control is plain HTTP
